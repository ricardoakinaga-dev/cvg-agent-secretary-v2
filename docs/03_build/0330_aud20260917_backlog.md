## Regras para o executor

Cada task começa pela leitura dos quatro documentos CVG e pela revisão do gate aplicável. O executor congela a SPEC detalhada, negativo, critérios e paths antes de código; preserva alterações atuais; registra comandos, ambiente, candidato, PASS/FAIL/SKIP, logs sanitizados e crítica distinta. A saída de BUILD é `IMPLEMENTED`, seguida de AUDIT; `VERIFIED` só com evidência fresca. Prioridade P0/P1 indica ordem de risco, não licença para atuar em sistemas reais. Onde a tarefa cruza banco/efeito/identidade, a prova deve atravessar a fronteira persistente/pública, não apenas mock.
