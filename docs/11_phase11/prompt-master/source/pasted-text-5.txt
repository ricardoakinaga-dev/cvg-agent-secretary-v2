# CONTINUAÇÃO FINAL — PHASE 11.15

## TRIPLE-AAA CERTIFICATION, PROMOTION & FINAL ACCEPTANCE

> Continuação direta do item 314. Todos os requisitos dos itens 1–313 permanecem obrigatórios e cumulativos.

---

# 314. SOURCE-OF-TRUTH GATE

Prove por testes que o runtime diferencia:

```text id="nrc2ik"
MODEL_PROPOSAL
USER_STATEMENT
INFERENCE
VERIFIED_FACT
SYSTEM_STATE
```

Somente fontes autorizadas podem produzir fatos operacionais confiáveis.

---

# 315. FACT AUTHORITY

LLM não pode transformar:

```text id="1vtcqk"
"I think appointment was created"
```

em:

```text id="3v0zlf"
appointment.created = true
```

sem evidência operacional.

---

# 316. GOAL SUCCESS GATE

Prove:

```text id="1flv5j"
tool returned success
```

não implica automaticamente:

```text id="1j82eq"
goal completed
```

Goal completion deve depender dos `SuccessCriteria`.

---

# 317. OBSERVE-RESULT GATE

Todo side effect relevante deve produzir ou permitir obter evidência verificável de resultado.

---

# 318. UNKNOWN OUTCOME GATE

Se efeito externo tiver outcome incerto:

```text id="vd6ah5"
UNKNOWN
```

deve ser preservado.

Não converter automaticamente para:

```text id="d2mwhf"
FAILED
```

nem repetir cegamente.

---

# 319. RECONCILIATION GATE

Para efeitos que possam retornar outcome desconhecido:

```text id="d3bj0q"
UNKNOWN
 ↓
RECONCILE
 ↓
SUCCEEDED / FAILED / STILL_UNKNOWN
```

---

# 320. HUMAN TAKEOVER GATE

Prove concorrência:

```text id="gxk3gv"
automatic outbound prepared
+
human takeover
```

antes do commit do efeito.

Resultado obrigatório:

```text id="f66qxk"
automatic outbound suppressed
```

---

# 321. STATE RECOVERY GATE

Após restart:

```text id="qovzgr"
goal
plan
steps
budget
approval
leases
effect journal
evaluation
```

devem permanecer coerentes.

---

# 322. NO RESET ATTACK

Restart não pode resetar:

```text id="mczkhw"
budget
attempt count
replan count
approval usage
```

---

# 323. FENCING GATE

Worker com lease antigo não pode confirmar step depois que novo worker adquiriu lease superior.

---

# 324. CONCURRENCY GATE

Execute testes simultâneos para:

```text id="r3bbrd"
goal update
step claim
approval consumption
outbox effect
human takeover
scheduler execution
```

---

# 325. DETERMINISTIC REPLAY

Quando possível, registre informações suficientes para reconstruir uma execução controlada sem repetir side effects.

---

# 326. EXECUTION SNAPSHOT

Cada Goal deve poder apontar para:

```text id="v5d2va"
agentVersion
promptVersion
policyVersion
toolVersions
modelProfile
```

usados na execução.

---

# 327. SESSION PINNING

Preserve session version pinning já existente.

Não permita upgrade silencioso de Agent/Policy durante execução ativa sem migration policy explícita.

---

# 328. PROMPT PINNING

Prompt version relevante deve ser auditável.

---

# 329. POLICY PINNING

Decisões históricas devem registrar policy version usada.

Para execução futura de ação ainda não realizada, revalide policy quando necessário.

---

# 330. TOOL VERSION PINNING

Tool execution deve registrar versão do contrato utilizado.

---

# 331. AGENT VERSION PINNING

Goal deve saber qual AgentVersion o iniciou e qual executou cada step.
