# 611. COMMIT-BOUND CERTIFICATION

Se autorizado a criar commits, a certificação deve referenciar exatamente o commit candidato final.

Obrigatório:

```text id="8cveqb"
candidateCommit == HEAD
manifestCommit == HEAD
evidenceCommit == HEAD
releaseManifestCommit == HEAD
```

---

# 612. POST-CERTIFICATION MUTATION

Se qualquer arquivo coberto pela certificação mudar depois:

```text id="gjft2x"
certification = STALE
```

---

# 613. DOC-ONLY CHANGE

Não presuma automaticamente que mudança documental é irrelevante.

Implemente política explícita para distinguir:

```text id="7ptzke"
behavior-changing
certification-relevant
certification-neutral
```

---

# 614. BEHAVIOR HASH

Considere gerar hash da superfície comportamental relevante para distinguir reanchor documental seguro de mudança de runtime.

Não substitua commit binding sem rationale forte.

---

# 615. REANCHOR

Se houver commit posterior estritamente documental:

um reanchor só é permitido quando script provar que nenhum artifact comportamental mudou.

# 706. FINAL SUCCESS STATE

O trabalho de implementação só pode ser considerado concluído quando:

1. todas as mudanças independentes de fatores externos forem implementadas;
2. todos os testes locais aplicáveis forem executados;
3. blockers externos forem explicitamente registrados;
4. evidence estiver coerente;
5. final audit estiver produzido;
6. certification calculus tiver sido executado.
