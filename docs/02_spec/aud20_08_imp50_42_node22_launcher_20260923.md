## Goal and boundary

Provide a local command that runs a supplied command with exactly Node
`22.23.2`, or exits with an actionable error when that exact local runtime is
not installed. This implements the existing Node-runtime requirement in
`docs/01_prd/0028_aud20_08_state_node_reconciliation.md` and item 42 of the
[Plan50 backlog](../03_build/0341_plan50_backlog_20260923.md).

The wrapper is for a POSIX development shell with a local NVM installation. It
must not install or download Node, change a user shell profile, alter the
existing `.nvmrc`/`.node-version` pins, or weaken `docs:check`'s rejection of an
incorrect runtime. CI runtime selection, Docker images, and production runtime
are outside this follow-up.

## Proposed command and behavior

Public examples:

```bash
npm run node22 -- npm run docs:check
npm run node22 -- node --version
```

Proposed implementation:

1. Add `scripts/with-node22.sh` and expose it through the package script
   `node22`.
2. Resolve the repository root from the script location. Keep it separate from
   the child command's working directory.
3. Require `.nvmrc` and `.node-version` to contain exactly `22.23.2`; fail with
   a stable diagnostic if either pin is missing or differs.
4. Resolve the local NVM root from `NVM_DIR`, falling back to the standard
   `$HOME/.nvm` directory. Use only the already-installed
   `versions/node/v22.23.2/bin` directory.
5. Require an executable `node` there and verify that it reports
   `v22.23.2`. If absent, fail with a diagnostic that asks the developer to
   install the pinned runtime through their approved local setup. The wrapper
   must not invoke a downloader, package manager, shell-profile edit, or
   `nvm install`.
6. Prepend that directory to `PATH` and `exec` the supplied command and
   arguments as separate argv values. Preserve the original invocation cwd and
   other environment variables. When npm supplies `INIT_CWD`, run the child
   from that original npm invocation directory; npm otherwise launches package
   scripts from the package root. If `INIT_CWD` is absent or empty (direct
   helper invocation), use the helper's starting directory. Fail with a stable
   diagnostic if the selected directory cannot be entered. Do not use `eval`
   or reparse arguments as shell source. See npm's documented
   [working-directory behavior](https://docs.npmjs.com/cli/v11/using-npm/scripts#working-directory-for-scripts).
7. Reject an empty command with usage text and a nonzero exit code.

The bare `npm run docs:check` continues to fail closed when the invoking Node
runtime is incompatible. Developers opt in to the launcher command explicitly.

## Acceptance criteria

- **N22-01:** Starting from Node `24.20.0`, the public command runs
  `node --version` under `22.23.2`.
- **N22-02:** A temporary NVM layout without the pinned runtime exits nonzero,
  identifies `22.23.2`, gives an actionable local-install direction, and makes
  no network request or installation attempt. The test places `nvm`, `npx`,
  `curl`, `wget`, and package-manager stubs earlier on `PATH`; each stub writes
  a sentinel if invoked, and the test asserts that none ran.
- **N22-03:** Missing, malformed, or mismatched `.nvmrc` / `.node-version`
  fails before invoking the requested command.
- **N22-04:** Empty command fails with usage text and nonzero status.
- **N22-05:** Arguments containing spaces and metacharacters arrive unchanged;
  the requested command sees the original invocation cwd and ordinary
  environment values. The public npm command is tested from the repository
  root and from a temporary directory outside it, including a path containing
  spaces; in both cases the child sees the directory from which the caller ran
  npm.
- **N22-06:** Bare `npm run docs:check` under Node 24 still reports
  `node_runtime_mismatch`; the launcher does not relax the checker.
- **N22-07:** Focused launcher tests, `docs:check` under Node 22, format check,
  typecheck, lint, full unit suite, and `npm run test:coverage` pass after
  implementation. Run the complete applicable build gates for the sprint
  before accepting `IMP50-42`.
- **N22-08:** With `NVM_DIR` set, the launcher selects that installation even
  when `$HOME/.nvm` is absent or contains a different test runtime.
- **N22-09:** With `NVM_DIR` unset, the launcher resolves the exact runtime
  from a temporary `$HOME/.nvm` layout.
- **N22-10:** Invoking the public command with `npm --prefix <repo> run node22
-- <probe>` from outside the repository preserves the original invocation
  directory for the child, using npm's `INIT_CWD` value rather than npm's
  package-root script directory.

## Negative cases

Test absent NVM directory, missing exact-version directory, non-executable Node,
reported-version mismatch, each pin mismatch independently, missing command,
failed child exit propagation, argument preservation, execution from a
working directory outside the repository, `INIT_CWD` handling via the public
npm command, `NVM_DIR` precedence, and the `$HOME/.nvm` fallback. On the
missing-runtime case, installer/downloader stubs must remain uncalled. Tests
must use temporary synthetic files and must never attempt network access.

## Rollback

test, and the documentation paragraph. Preserve the already-approved Node
pins, checker behavior, and history. Rollback requires only a local revert of
